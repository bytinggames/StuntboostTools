Schnittstelle Blender -> Game Anforderungen:
* only editor visible
blender object based:
* visibility: None, Baked, Dynamic
* aggregate: none, transmissive, solid
* enabled: bool
some objects should start disabled. F.ex. tutorial objects. (invisble and no interaction)
* methods (and setters): string[] // example: [ "Disable()", "AmbientColor(FF88AA)" ]
property setters every entity has:
* Outlines: bool
example: you might want to turn that off for duct tape
* CastShadowsFromLights: []
list of light sources (names). this should be automatically set by some kind of bounding volume during the bake script. This is too mundane and error prone to do per hand. There is one light source that is generated by running the bake script. It's name should always be the same, maybe "sun". In this case castShadowsFromLights=["sun"] would mean this object casts only shadows from the sun. When this array is empty, no realtime shadows are cast.
When deciding which lights to add to this array, one should ask the question: From which lights can the player hide behind these objects? Can he even stand there or would he die immediately? Player = any dynamic object in this case
things I need to see instantly when working with blender:
* name: string
Need a way to reference objects in blender but also from C#
* C# type/ctor: string
example: Entity() or Text(some.loca.key) or Text(some.loca.key, 3, FF88AA) or EyePupil(doorName)
[name]=[type]([parameters]) would be a style I would like to keep. Removing all of the other additions we had before.
This would make such things possible:
no name, but purpose clear because of class name: =PreviewCamera(1)
no name, but purpose clear through ctor parameters: =Text(some.loca.key) oder =Spawn(intro)
default Entity object without specifying Entity(): some_name

blender material based:
* solidType: Normal, RampHorizontal, RampVertical, Kill // only relevant, when object aggregate is solid
